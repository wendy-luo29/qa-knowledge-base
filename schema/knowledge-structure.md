# 知识库目录与分层规范

## 1. 两层分离

| 层 | 位置 | 可变性 | 内容 |
| --- | --- | --- | --- |
| 证据层 | 项目仓 `requirements/` 或交付物库 `UR-*/` | 不可变快照 | 需求原文、接口契约、评审记录、AC 清单 |
| 结论层 | 知识库实例 | 可维护 | 业务规则、踩坑、术语、影响索引、变更记录 |

禁止在结论层存放需求原文或接口文档快照；结论层只放经确认的判断与来源引用。

## 2. 目录结构

```text
knowledge/                       # 知识库实例（仓库名可自定义）
├── INDEX.md                     # 入口索引：按问题导航到规则
├── impact-index.yaml            # 机读影响索引
├── rules/
│   └── <module>/
│       └── <feature>.md         # 业务规则，带 front-matter
├── gotchas/
│   └── gotcha_001_<topic>.md    # 踩坑，编号三位递增
├── changelog/
│   └── yyyy-MM-dd_<topic>.md    # 规则变更记录
└── references/
    ├── glossary.md              # 术语
    ├── db_schema.md             # 关键表结构
    └── apifox.md                # 接口文档入口
```

## 3. 分层规则

| 规则 | 说明 |
| --- | --- |
| 按模块建目录 | `rules/<module>/<feature>.md`，禁止按版本建子目录 |
| 版本写在 front-matter | 文件名不带版本号 |
| 编号不复用不跳号 | AC、用例、踩坑编号只增不改 |
| 写入入口唯一 | 只有需求评审通过的环节可写 `rules/` |
| 变更同提交 | 规则改动与影响索引改动必须在同一提交 |
| 时效复核 | 规则超过 180 天未复核触发告警 |

## 4. 与交付物库的关系

- 项目级稳定规则放交付物库 `Project-*/Common/知识库/`。
- 需求批次内的临时结论放 `UR-*/研发分析/`，确认后升级到 `Common/知识库/`。
- 公共仓只放规范与本文件，不放任何项目的业务规则。
